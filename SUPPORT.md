# OpenTLV Support

Start with the affected repository's README and technical guides. Search its issues
before opening a public Bug or Chore; include the version or commit and a minimal
reproducer. Use a blank issue for a question or proposal that does not fit the forms.
Support depends on maintainer availability; no response-time guarantee is implied.

| Topic | Owning repository |
| --- | --- |
| C engine, C++ API and TLV behavior | [Core](https://github.com/OpenTLV/opentlv) |
| Command-line tool | [CLI](https://github.com/OpenTLV/opentlv-cli) |
| Lua binding | [Lua](https://github.com/OpenTLV/opentlv-lua) |
| Python binding | [Python](https://github.com/OpenTLV/opentlv-python) |
| Rust crates | [Rust](https://github.com/OpenTLV/opentlv-rust) |
| Go module | [Go](https://github.com/OpenTLV/opentlv-go) |
| JavaScript/WASM binding | [JavaScript](https://github.com/OpenTLV/opentlv-js) |
| Documentation portal, navigation and publication | [Docs](https://github.com/OpenTLV/opentlv-docs) |
| Editor setup, bootstrap and integration | [Workspace](https://github.com/OpenTLV/opentlv-workspace) |
| Shared community policies and templates | [Community](https://github.com/OpenTLV/.github) |

Technical manuals and examples belong to their component repository even when
published through the Docs portal. If a public issue spans repositories, identify
the owners and link related issues without duplicating component implementations.

For suspected vulnerabilities, follow the affected repository's security policy or
the [shared private reporting route](https://github.com/OpenTLV/.github/blob/main/SECURITY.md).
For misconduct, follow the private reporting instructions in the
[Code of Conduct](https://github.com/OpenTLV/.github/blob/main/CODE_OF_CONDUCT.md).
Do not use public support issues for either kind of sensitive report.
